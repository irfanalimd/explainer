# event-loop: sources

Every real-world claim in `examples/event-loop/lesson.mjs` names one of these as `[id]`. Web pages, papers and source code
were opened and each claim read there (DOIs checked on Crossref, source read at the cited lines). Books, and sites
that refuse scripted requests (Intel, MIT Press, ACM), were checked by metadata only: see the README's Checks.

| id | Title | By, year, where | What it supports | Cited in |
|---|---|---|---|---|

| `whatwg-render-task` | [Refactor event-loop processing model to perform rendering as a task (pull request #10007)](https://github.com/whatwg/html/pull/10007) | WHATWG, 2024, github.com/whatwg/html | since January 2024 the standard updates the rendering in a task; before, it was a step of the loop between tasks | `steps.arrive` |
| `whatwg-timers` | [HTML Living Standard, §8.6 Timers: the timer initialisation steps](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#timer-initialisation-steps) | WHATWG, 2026, html.spec.whatwg.org | a due timer queues a task; past a nesting level of 5, a timeout under 4 ms becomes 4 ms | `steps.script`, `steps.arrive`, `steps.chunk` |
| `ecma-promise` | [ECMAScript Language Specification, promise jobs](https://tc39.es/ecma262/#sec-newpromiseresolvethenablejob) | Ecma TC39, 2026, tc39.es/ecma262 | a handler that returns a promise costs extra jobs before the next handler runs | `steps.settle` |
