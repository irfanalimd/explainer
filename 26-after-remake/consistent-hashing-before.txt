Consistent hashing: Adding a server moves one arc of keys, not all of them
level core · 3 stories · 3 knobs (Servers, Keys, Seats per server)

HOOK      Several servers share the keys. Add one more server: how many keys have to move?
GOAL      Share keys among servers so that a server joining or leaving moves only the keys it must.
OBJECTIVES
  o-mod: Compute roughly how many keys the remainder way moves when one more server joins.
  o-owner: Perform a lookup on the ring: find the server that stores a key, wrapping past the top.
  o-add: Predict which keys move when a server joins the ring, and which server they come from.
  o-leave: Explain where a leaving server's keys go, with one seat per server and with many.
  o-even: Explain why one seat per server shares the ring unevenly, and how more seats even it out.
PICTURE   guests around a round table
  table   a round table whose seats are numbered all the way round  =  the hash ring: every number from 0 to 2^32 − 1  (ring)
  seat    the seat a host's name points to  =  a server's position, the hash of its name  (hash)
  guest   a guest who walks clockwise and sits with the first host  =  a key, stored on the first server clockwise
  stretch the stretch of table a host looks after  =  a server's arc, from the seat before it to its own  (arc)
  chair   a newcomer pulling up a chair in one stretch  =  a server joining: it takes the keys just before its seat
  chairs  one host keeping several chairs around the table  =  virtual nodes: many seats for one server  (virtual node)
  breaks  Real guests pick a free seat. Here nobody chooses: a hash fixes every seat, so seats can
          bunch up and one host can get a huge stretch.
BELIEFS
  m-fair: “Adding a server only moves its fair share of the keys, whatever rule places them.” With
          the remainder way, dividing by a new number changes almost every remainder, so most keys
          move.
  m-reshuffle: “Any change in the servers reshuffles keys everywhere, on the ring too.” On the ring,
               only the keys in the arc that changes hands move; every other key keeps its server.
  m-even: “When a server leaves, its keys spread evenly over the servers that are left.” Each key
          walks on clockwise, so with one seat per server they all land on the next server.
WORDS
  hash: (a name's fixed number) A scrambling recipe that turns a name into a big number, the same
        number every time.
  ring: (the circle of numbers) Every possible number from 0 to about 4.3 billion, bent into a
        circle that wraps back to 0.
  arc: (a server's stretch) The stretch of the circle from one server's seat back to the seat before
       it.
  virtual node: (an extra seat) One of several seats a single server takes on the circle.

   ▸ Chapter 2 of 6 · One more server
     about     Now there are 5 servers, so every key's number is divided by 5 instead of 4. The
               remainders change, and each key follows its new remainder.
     so far    Each key sits on server `hash % 4`.
     now       Add one server, so every key divides by one more.
     done when The “moved, remainder” counter shows how many keys changed box.
     PREDICT  db05 joins, so each key now goes to server hash % 5. How many of the 16 keys change
              server?
              A) About 3, one in 5: the new server's fair share
                 → A fair share is what the ring moves, not the remainder way. A key stays only if
                   its remainders by 4 and 5 match, so on average 4 in 5 move. Here 14 of 16 did.
                   [m-fair]
              B) About half of them
                 → A key stays only if its remainders by 4 and 5 match: on average 1 key in 5, so
                   about 4 in 5 move. With only 16 keys luck swings the count; here 14 of 16 did.
              C) Most of them: about 4 in every 5   ✓
                 → On average, yes: a key stays only if its remainders by 4 and 5 match, 1 key in 5.
                   With only 16 keys luck swings the count; here 14 of 16 did.
              why: A key keeps its server only when its remainders by 4 and by 5 agree: on average 1
                   key in 5.
   2  ★ db05 joins, so every key now uses `hash % 5`: 14 of 16 change server.   ‹more.move›
        why       Changing the divisor changes most remainders, so the keys are dealt out again
                  almost from scratch.
        look      m.db05
        · cost    On average 4 keys in every 5 move, the fraction N/(N + 1); one in 5 is all that
                  must. Here 14 of 16 moved.
        · how     A key keeps its server only if hash % 4 equals hash % 5. That holds for 1 number
                  in 5, so the bigger the cluster, the worse it gets.
        · edge    With only 16 keys, luck swings the count above or below the average; with a
                  million keys the share moved lands within 0.1% of N/(N + 1).
        · real    This is the problem the ring was invented for. Karger et al. wanted web caches
                  that could come and go, and a hash that “changes minimally as the range of the
                  function changes”. Tom White's 2007 write-up starts from this same reshuffle.
        · source  Karger et al. 1997; White 2007

                  others.
        look      t.db01, t.db03, t.db04, t.db02
        picture   the seat a host's name points to = a server's position, the hash of its name
        · how     A server's arc runs from the seat before it up to its own seat, and it stores
                  every key that lands there.

                  within a constant factor of fair. Their work grew into the business plan for
                  Akamai, the content delivery network; two of the authors, Tom Leighton and Danny
                  Lewin, founded it.
        · source  Karger et al. 1997; Leighton 2002

     about     A new server pulls up a chair inside an arc. It takes only the keys between the seat
               before its own and its own; every other key stays put.

     now       Seat one more server, db05, on the ring.

  12  db05 joins at `0xac98_d9e0`, inside db04's arc. It waits, empty.   ‹add.join›
        why       Watch which keys now meet db05 first on their clockwise walk.
        look      t.db05, t.db04
        picture   a newcomer pulling up a chair in one stretch = a server joining: it takes the keys
                  just before its seat
        · how     A real server copies its keys first and starts answering for them after, so
                  nothing is lost while they move.
        · real    In Dynamo the existing nodes hand over the key ranges a new node now owns (§4.9).
        · source  DeCandia et al. 2007, §4.9
     PREDICT  db05 takes over part of db04's arc. Which of the 16 keys have to move?
              A) Only the keys between db05 and the server before it   ✓
                 → Right. A key moves only if a seat of db05's is now first on its clockwise walk:
                   here 3 of 16.
              B) Keys from all around the ring, like the remainder way
                 → If you thought any change reshuffles everything: on the ring a key moves only if
                   db05 is now first on its walk. Here 3 of 16 moved; 13 stayed put. [m-reshuffle]
              C) All of db04's 4 keys
                 → Only keys that now meet one of db05's seats first move, so it depends on where
                   those seats land. Here 3 of 16 moved.
              why: db05 splits one arc. Only keys between the server before it and db05's seat now
                   meet db05 first.
  13  ★ db05 takes 3 keys from db04; the other 13 stay put.   ‹add.move›
        why       Every other key's clockwise walk still ends at the same seat, so nothing else
                  changes.
        look      db05, k.feed:home, k.post:12, k.sku:1182
        · cost    On average K/(N + 1) keys move, the least any rule can: here 3 of 16.
        · how     Karger et al. call this smoothness: a new server takes keys only from the arcs its
                  seats split.
        · real    Dynamo adds a node the same way; only the nodes that owned its new ranges send
                  data (§4.9).
        · source  Karger et al. 1997; DeCandia et al. 2007, §4.9

     about     On the ring, only the keys in the split arc moved: on average one key in 5. The
               remainder way moves on average 4 keys in 5, and every moved key is data copied over
               the network.
     so far    The new server took keys only from the arc it split; every other key stayed.
     now       Compare the keys each way moved, and check how evenly the ring is shared.
     done when The two moved counters sit side by side: the ring's and the remainder way's.
  14  ★ Ring: 3 of 16 moved; one in 5 is 3.2. Remainder way: 14.   ‹result.moved›
        why       On average the ring moves 1 key in 5; the remainder way moves 4 in 5.
        look      k.feed:home, k.post:12, k.sku:1182
        · cost    Ring: about K/(N + 1) keys on average (3.2 here). Remainder way: about K × N/(N +
                  1).
        · edge    With few keys, luck can flip a single run, so compare the averages, not one count.
        · real    Jump consistent hash (Google, 2014) also moves just 1 key in N + 1 and needs no
                  ring in memory, but servers can only join or leave at the end of the list.
        · source  Lamping & Veach 2014
  15  But one seat each shares the ring unevenly: db03 now owns 49% of it.   ‹result.uneven›
        why       db03 owns 2.5× the average share, so it stores and serves that much more.
        look      db03
        · how     The meter is the biggest share divided by the average share, so 1× would be
                  perfectly even.

   RECAP
     1. The remainder way moved more keys than the ring when one more server joined.
     2. On the ring, each key sits with the next server clockwise.
     3. A new server took only the keys just before its new seats.
     4. The seats share the ring unevenly: the busiest server owns more than its fair share.
   TAKEAWAY  On a ring, a new server takes only the keys just before its seats. The remainder way
             moves more: on average N keys in N + 1.

   ▸ Chapter 4 of 5 · A server leaves
     about     A server leaves the table. The keys it held walk on clockwise to the next seat still
               there; no other key moves.
     so far    Each server now owns 8 small arcs around the ring.
     now       Take a server with the most keys, db01, off the ring.
     done when Only db01's keys change colour; every other key keeps its own.
   9  db01 is leaving. It holds 4 keys, 32% of the ring.   ‹leave.drain›
        why       No server holds more keys, so this leave moves as much data as any could.
        look      db01, k.user:77, k.user:9, k.cart:12, k.logo.svg
        · how     Its seats dim while it drains. They leave the ring only as its keys move, so every
                  key always has a server.
     PREDICT  Where do db01's 4 keys go?
              A) To the next server clockwise of each of its 8 seats   ✓
                 → Right. Each key walks on to the first seat still there: here 4 keys went to db03,
                   db02 and db04.
              B) Spread evenly over the other servers
                 → Nobody shares the keys out: each key walks on clockwise to the next seat still
                   there. Here db01's 4 keys went to db03, db02 and db04. [m-even]
              C) Every key in the cluster is reshuffled
                 → If you thought a leave reshuffles everything: only db01's keys move, since no
                   other key's walk passed its seats. The rest keep their server. [m-reshuffle]
              why: Each key walks clockwise to the first seat still there. db01's seats sat in
                   different places, so the keys reach different servers.
  10  ★ Each key walks on clockwise from its spot: 4 keys spread over db03, db02 and db04.   ‹leave.move›
        why       db01's seats sat in different arcs, so its keys reach different next seats.
        look      db03, db02, db04, k.user:77, k.user:9, k.cart:12, k.logo.svg
        picture   a guest who walks clockwise and sits with the first host = a key, stored on the
                  first server clockwise
        · how     No key that db01 did not hold moves: their walks never passed its seats.
        · edge    Real stores keep copies: Dynamo writes each key to the next few distinct servers
                  clockwise, so the next server already has a copy when one leaves (§4.3).
        · real    Dynamo's paper gives this spread as the reason for many seats: a failed node's
                  load is shared by the rest (§4.2).
        · source  DeCandia et al. 2007, §4.2, §4.3

   ▸ Chapter 5 of 5 · Result
     about     With many seats per server, each server owns many small arcs. A leaver's keys can
               spread out, and on average the shares stay closer to even than with one seat each.
     so far    Only the leaver's keys moved, each to the next seat clockwise.
     now       See how evenly the servers that are left share the ring.
     done when The busiest-server meter shows the share against the average.
  11  ★ db04 is now the busiest, at 1.2× the average share. With 256 seats each: 1.1×.   ‹result.vnodes›
        why       More seats even out the shares, but each seat is one more arc to track and copy.
        look      db04
        · cost    Worked out for the servers left: 1.1× with 64 seats each, 1.1× with 256. Past a
                  few dozen seats, more buys little.
        · edge    Random seats even out slowly. Dynamo moved to equal-size slices of the ring handed
                  out evenly, its best-balanced strategy (§6.2).
        · real    Cassandra 4.0 cut its default from 256 random seats per node to 16, placed by an
                  allocator so they still spread evenly. With 256 random seats, every node shared
                  data with so many others that losing a few nodes could make some data unavailable.
        · source  DeCandia et al. 2007, §6.2; Cassandra 2024; Cassandra 2020

   RECAP
     1. A server's share is the sum of its arcs, and more seats make more, smaller arcs.
     2. When a server left, each of its keys walked on to the next seat clockwise.
     3. Only the leaving server's keys moved on the leave.
   TAKEAWAY  With many seats per server, the shares tend to even out, and a leaving server's keys
             can spread over several neighbours.
   CAN NOW   o-mod, o-owner, o-add, o-leave, o-even
