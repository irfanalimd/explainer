MapReduce: Counting words with a team of machines
level core · 4 stories · 4 knobs (Reading machines, Counting machines, Add up repeats first, Text to count)

HOOK      Each machine reads only part of the text. How do they still count every word exactly, none
          missed or counted twice?
GOAL      Count every word of a text exactly, with machines that each read only part of it.
OBJECTIVES
  o-split: Say why the text is cut into pieces and read in parallel, and what that buys.
  o-hash: Explain why every copy of a word must reach the same counter, and how a hash does it
          without asking anyone.
  o-fail: Say why a crashed or slow reading task can simply run again, and which finished work must
          re-run.
  o-cost: Name what the shuffle costs, and how adding up repeats early cuts it.
PICTURE   a library counted by a team
  master  the coordinator handing out shelves  =  the master  (master)
  split   one shelf of books  =  one piece of the text (a split)  (split)
  mapper  a helper tallying their shelf  =  a reading machine (a mapper)  (mapper)
  slip    a tally slip “fox: 1”  =  a record `(fox, 1)`: the word, and the number 1
  hash    “all slips for one word go to one person”  =  a fixed rule on the word's letters (a hash) that picks one counting machine  (hash)
  reducer the person adding them up  =  a counting machine (a reducer)  (reducer)
  output  the noticeboard  =  the output: a folder with one file per counting machine
  breaks  Helpers would talk to agree who counts which word. Machines never talk about it: each one
          runs the same rule on the word and gets the same answer.
BELIEFS
  m-central: “Each machine counts its piece, and one machine adds it all up at the end.” Then one
             machine would add up every slip. Instead each word's slips meet on one counter, so the
             adding is shared too.
  m-even: “Spreading the slips evenly over the counters is best.” Copies of one word would land on
          different counters, and none could give its full count.
  m-lost: “A crashed machine's words are lost, so the count comes out short.” Its piece is still in
          the input. Reading it again gives the same slips.
  m-restart: “One failure restarts the whole job.” Only the failed machine's tasks run again.
  m-wait: “The job has to wait for its slowest machine.” A backup copy of the slow piece on a free
          machine gives the same slips. The first copy to finish wins.
  m-skip: “Skipping a slow piece is a fair price for finishing on time.” Its words would never be
          counted. MapReduce never trades a correct count for speed.
WORDS
  master: (the coordinator) The machine that hands out pieces of work, keeps track of them, and
          notices when a machine fails.
  split: (one piece of the text) One piece of the input, read by one machine, like one shelf of a
         library.
  mapper: (a reading machine) A machine running map: it reads one piece and writes a slip like (fox,
          1) for every word.
  hash: (a word's fixed number) A function that turns a word into a big number. The same word always
        gives the same number.
  shuffle: (sending each slip to its counter) The step where every slip travels to the machine that
           adds up its word.
  reducer: (a counting machine) A machine running reduce: it adds up all the slips for its share of
           the words.
  straggler: (a slow machine) A machine much slower than the rest, so everyone ends up waiting for
             it.
  combiner: (adding up early) Code that adds up repeats on the reading machine itself, before any
            slip is sent.
NUMBERS   words read * · sent between machines * · busiest counter's load * · tasks finished   (* in the dock)

   6  ★ the goes to reduce 0: its hash, 3 020 861 980, divided by 2 leaves remainder 0.   ‹shuffle.first›
        why       Taking turns would scatter one word's slips over several counters, and counters
                  never compare notes, so none would hold the full count.
        look      m0.s0.w0, r0
        picture   “all slips for one word go to one person” = a fixed rule on the word's letters (a
                  hash) that picks one counting machine
        · how     Each mapper has already divided its slips into 2 files, one per counter, and each
                  counter fetches its file from every mapper. The fetching starts early: the master
                  passes on each finished map's file locations as they come (§3.2). Only the sort
                  and the adding wait for the last map, which might still hold a slip they need.
        · cost    In this model 85 bytes cross the network: each slip's word plus a 4-byte count
                  (real formats add length headers, and a reader on the counter's own machine sends
                  nothing). In a cluster, network bandwidth is the scarce resource (§3.4).
        · edge    Python's own hash() of a string changes from process to process (hash
                  randomization) unless PYTHONHASHSEED is fixed, and can differ between Python
                  versions, so two machines could disagree. Real jobs use a specified hash; this run
                  uses FNV-1a.
        · code    `hash(word) % R` (lines 8–9)
        · source  J. Dean and S. Ghemawat, MapReduce: Simplified Data Processing on Large Clusters,
                  OSDI 2004, https://research.google/pubs/pub62/
